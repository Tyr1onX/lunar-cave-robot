## P4d 源码与接口背景

### ROS 数据源和节点

tzb_ws/src/lite_motion_planner/src/tzb_catch.cpp 将插值轨迹样本以 sensor_msgs/JointState 发布到 /tzb_catch/arm_joint_command。每次发布的 header.stamp 使用 this->now()，发布周期参数默认 100 Hz；轨迹输出循环使用 steady clock 和周期 sleep。正常轨迹结束时会再发布一次最终目标。消息没有动作 UUID、轨迹代号或源端命令序号。

tzb_ws/src/serial/driver/src/node.cpp 是 rm_serial_driver ROS 2 节点。它将命令映射到固定的 J1～J6 顺序、限速并发送 46 字节二进制扩展帧；原实现不检查消息时间戳，首次收命令后无限保留目标，命令停更或非法输入后仍周期发送旧目标，重连时也不清理旧目标。夹爪订阅此前使用 transient-local QoS，可能收到持久历史值。上行有效响应是完整数据帧和全局序号检查，不包含逐轴新鲜度/驱动故障字段。

### 46 字节协议关系

本次保持既有 wire layout：

| 字节 | 含义 |
| --- | --- |
| 0 | 0xA5 |
| 1～12 | 三个 little-endian float32：历史底盘 vx/vy/wz 前缀 |
| 13～14 | 0x4A, 0xB5 |
| 15 | arm_command_enabled：STM32 采纳本帧关节目标的协议位 |
| 16～19 | 上位机发送序号（STM32 当前固件不以此实现去重/会话防重放） |
| 20～43 | J1～J6 六个 float32 目标 |
| 44 | 有符号夹爪命令：1 关闭、-1 打开、0 保持 |
| 45 | 0x4B |

46 字节是机械臂 USB CDC 链路的既有复合帧。STM32 源码把底盘前三个 float 解析后丢弃；该前缀不是六轮底盘 USART1 控制接口。P4e 不把这 46 字节帧当作底盘运动驱动。

**字节 15 清零只是不采纳本帧的关节目标，不是电机失能、制动或急停，也不承诺清除 STM32 已有目标。** P4d 审计记录的固件路径是在流目标停更后约 100 ms 将流速度目标收敛至零并继续执行关节闭环；该源码行为未做带载验证。夹爪字段置 0 的语义是 hold，不是松爪。

## P4e 上位机状态门控

驱动当前状态为：

1. DISARMED：节点启动/进程重启后的默认状态。忽略并不缓存命令，串口帧字节 15 为 0、夹爪为 0。
2. ARMED_WAIT_COMMAND：操作者调用 enable 服务，且串口打开、最近收到有效整帧反馈、各关节反馈有限且在配置限位内、上游命令源已静默。节点记录本次使能时的 ROS 时间戳水位。
3. ACTIVE_HOST：只在此状态接收新的完整目标并发送字节 15=1。有效消息的 steady-clock 接收时刻刷新命令租约；周期发送器重发串口帧不会续租。
4. FAULT_LATCHED：命令租约/反馈超时、活动状态下收到非法/过期/重复或非单调时间戳目标、无效夹爪值或串口发送/重连异常时锁存。清除关节目标和夹爪缓存；串口发送字节 15=0、夹爪 0。反馈恢复或端口重开不会自行离开此状态。

ROS 接口：

- 状态诊断：/serial/arm_safety/status（volatile 的 std_msgs/String），包含当前状态、故障原因、整帧反馈年龄、命令年龄/候选租约、无效反馈计数、响应序号丢帧数、串口打开状态，并明确报告 per_joint_feedback_health=unavailable_in_46B_response。
- 人工清故障：/serial/arm_safety/reset（std_srvs/Trigger）。仅故障锁存状态可用；要求串口打开、近期有效整帧、测量位置有限且处于配置限位范围内、上游命令静默。成功后仍回到 DISARMED。
- 人工使能：/serial/arm_safety/enable（std_srvs/Trigger）。要求 DISARMED、反馈和串口健康、上游静默；仅进入 ARMED_WAIT_COMMAND。还必须收到时间戳严格晚于使能水位、晚于上一条命令、完整有限且在限位范围内的新 JointState，才进入 ACTIVE_HOST。
- 故障后必须先 reset、再 enable、再给新命令；上游持续发布时 reset/enable 会被拒绝。夹爪订阅改为 volatile，且只在 ACTIVE_HOST 接受新夹爪指令。

命令校验拒绝零/负秒或无效纳秒时间戳、过旧/超前消息、非递增时间戳、非恰好六个名称/位置、缺失/重复关节、NaN/Inf、float 转换溢出和 URDF 配置范围外的位置。速度限位配置也必须是六个有限正数，避免原来零限速值导致单步直接跳到目标。

当前配置中的命令租约 0.1 s、消息时间戳最大年龄 0.1 s、未来容忍 0.05 s、整帧反馈超时 0.5 s、重新使能静默窗 0.1 s 都是可配置的初始/候选值。它们不是经实机安全验证的最终阈值。100 ms 命令年龄/租约只能由后续满载时序、真实上游发布行为、STM32 停止动态与负载防坠评估后确认。

## 离线验收

ThinkBook：Ubuntu 22.04 / ROS 2 Humble。实际构建并运行本分支的 rm_serial_driver 可执行节点，通过脚本创建的 /dev/pts/* 虚拟串口与模拟 STM32 对端通信。虚拟对端发送版本 1 的 35 字节反馈，验证驱动真实读写和 ROS 服务/话题行为；没有触碰物理串口或硬件。

最终 P4e PTY 运行结果：

- 启动帧长度、0xA5/0x4A/0xB5/0x4B 字节布局有效；启动状态 disabled，夹爪 hold。
- 新鲜六关节命令进入 46 字节帧，校验关节顺序、方向/偏置转换及浮点目标；活动夹爪值写入字节 44。
- ROS 上游停发后命令租约过期，状态锁存、帧字节 15/夹爪清零，后续无旧目标重新使能。
- 上游仍发布时 reset 和 enable 均被拒绝。
- 过期时间戳、未来时间戳、NaN、Inf、越限及关节不完整命令均拒绝并锁存。
- 模拟停止有效反馈后触发整帧反馈超时；反馈缺失期间 reset 被拒绝，反馈恢复后也不会自动清故障，需人工 reset。
- 活动态反馈序号回退视为 STM32 控制器重启，锁存上位机并等待人工恢复。
- PTY 断开并将相同设备链接切换到新 PTY 后，驱动重连；新连接仍 disabled，旧命令不自动恢复。
- 对活动节点执行进程组 SIGKILL 并重启真实节点：新序号 epoch 起始帧 disabled、夹爪为 0；只有人工 enable + 新命令才输出 enabled 帧。
- 节点重启和 PTY 重连测试证明 ROS 驱动没有自动重发它缓存的旧目标。它们不证明 STM32 在主机断流期间的物理减速、抱持或防坠行为。

最新一次 5 秒、隔离 ROS_DOMAIN_ID 的运行时序探针（合成 rclpy 100 Hz JointState 发布器；不是 tzb_catch 真实轨迹在完整规划负载下的测量）：

| 测量 | 样本 | 中位 | P99 | 最大 |
| --- | ---: | ---: | ---: | ---: |
| ROS 2 发布定时器间隔 | 499 个间隔 | 10.001 ms | 10.177 ms | 10.246 ms |
| 驱动向 PTY 发送 46 字节帧间隔 | 513 个间隔 | 9.970 ms | 10.740 ms | 10.898 ms |

该探针仅表示 ThinkBook 上此 ROS 2 与 PTY 测试负载的调度表现。没有覆盖真实 tzb_catch 轨迹处理计算、Nav2/Point-LIO、系统长期高负载或实物电机动态；不能据此认证 100 ms 为最终安全租约。

## 已修复 / 未覆盖风险

| 类别 | 状态 |
| --- | --- |
| 上位机无限重发缓存关节目标 | 已修复：独立租约、失效清缓存、锁存故障，周期帧不续租。 |
| 旧/不完整/非有限/越限命令 | 已修复：严格时间戳、全关节完整性、有限值和限位校验。 |
| 上位机串口重连及 ROS 进程重启后自动恢复 | 上位机已修复：故障/启动均不自动使能，必须 reset、enable 和新命令。 |
| 夹爪历史目标跨故障、重启重放 | 已修复：驱动缓存清零为 hold，订阅不再请求 durable 历史，非 ACTIVE 指令忽略。 |
| 整帧反馈静默/错误协议帧 | 上位机新增全帧新鲜度、响应序号丢帧计数和状态诊断。 |
| 单个 CAN 关节反馈停更、电机错误/过温 | 上位机能力不足：35 字节 STM32 回复只含整帧序号和全局有效位，不能确认六轴分别新鲜/健康。需 STM32 与协议增加逐轴状态。 |
| CAN 断路、单轴电机状态错误、MCU Host 看门狗 | 未整改：本阶段未改固件。须固件按有效帧、命令租约和逐轴 CAN 状态做锁存与安全处置。 |
| 主机掉线时机械臂停车/保持和防坠 | 未验证：字节 15=0 不是急停。是否保持扭矩、轴级制动、全轴失能需基于电机抱闸/减速器/负载与防坠台架试验决定。 |
| 遥控失联后固件当前全轴 disable 与恢复逻辑 | 未修改。P4d 记录了故障解除后可能自动重使能；此行为和遥控急停物理回路必须在 STM32 安全整改阶段解决。 |
| 上游轨迹重放识别 | 部分覆盖、仍是阻塞项：JointState 没有 action/trajectory UUID；静默窗能挡住仍持续发布的源，水位能挡住带旧 stamp 的 DDS 样本，但无法辨认一个故障后被上游用新时间戳重新包装的旧轨迹。需 tzb_catch 取消/清空在途轨迹，并加入新的命令 epoch/单调序号，再由驱动核验。 |
| 重新使能权限 | 服务为普通 ROS Trigger，无操作者身份或物理二次确认。只能用于隔离离线验证，不能作为部署级使能。需要用户确认实体使能/遥控互锁与故障复位权限设计。 |
| 协议序号/完整性 | 当前 46 字节协议无 CRC；上位机序号不是 STM32 防重放依据。不能只依赖 ROS 检查替代固件校验。 |

## 实机运动前阻塞项与后续顺序

1. 先确认扭矩保持、遥控急停、反馈故障轴动作和人工恢复来源；核实六轴电机/减速器是否自锁、断电抱闸、整臂负载和失电下坠路径。这些选择会影响机械臂停机风险，本次没有代替确认。
2. 修改/评审 STM32：逐轴 CAN 接收年龄、驱动错误码/温度、有效 Host 帧和命令租约看门狗、故障锁存及显式恢复；输出逐轴反馈健康和可确认的状态。不能假装上位机当前已可检测这些状态。
3. 定义并验证新 ROS 命令会话/epoch、动作取消和序号来源端语义，确保 ROS 服务恢复时没有旧轨迹可继续发新时间戳。
4. 在确认后的软停/保持/制动策略下，于有机械承托、独立物理急停和监督的台架测减速距离、静态保持、反馈掉线、单轴故障和重启行为。先无负载再按批准步骤加载。
5. 在完整 ThinkBook P4/P5/Nav2/Point-LIO 负载下重复测命令/串口时序、CPU/调度压力和持续运行，再审定命令 lease、消息新鲜度和反馈超时参数。
6. 最后才考虑受控现场联调。P4e 不做连接、部署、烧录或合并。
