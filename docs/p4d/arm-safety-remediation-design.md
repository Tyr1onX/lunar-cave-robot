## 当前控制架构

### STM32 下位机

- 目标 MCU 为 STM32H723。工程由 CubeMX/HAL、FreeRTOS/CMSIS-RTOS2 与 others 下的应用层组成。USB CDC 接收回调把字节放入环形队列并唤醒 Host_Task；Host_Task 只在收到 RX 标志时运行 Host_Poll。机械臂控制任务持续更新关节轨迹、动力学/重力前馈和 MIT 控制帧；FDCAN3 回调按 motor_id 0x01～0x07 更新各电机缓存反馈。Error_tasks 每 10 ms 检查遥控失联/遥控急停条件。
- USB Host 下行是 46 字节、上行是 35 字节。下行 [0] 为 0xA5；[1..12] 是 vx/vy/wz 三个 float32 底盘预留字段；[13..14] 为 0x4A/0xB5；[15] 为关节使能/采纳位；[16..19] 为预留字段；[20..43] 为六个 float32 编码器弧度目标；[44] 为有符号夹爪命令；[45] 为 0x4B。固件将 [1..12] 解析为底盘速度后丢弃。上行只带 j1..j6 的角度、单个 inited 标志、递增帧计数和夹爪状态，不含逐轴健康位或逐轴反馈计数。
- 关节控制是流式位置目标。上游目标停止变化超过源码中的 stream_hold_time=0.10 s 后，固件规划器将流速度目标收敛到零，机械臂控制循环继续发送 MIT 控制帧并保持目标。这种受控减速路径与电机失能不同；实物负载下的停车距离、托举能力、温升和稳定性没有通过硬件试验。
- Remote.c 的 RC_ONLINE_TIMEOUT_MS 为 100 ms，RC_LOST_TIMEOUT_MS 为 3000 ms。100 ms 用于判定摇杆样本是否新鲜；Error_tasks 的挂起判定使用 3 s 遥控丢失或 S1/S2 同时下拨。当前 Remote_IsHostControl() 只读最近缓存的 S2 档位，不检查遥控在线状态。
- 遥控失联/软件急停进入当前 ArmHold 路径时，固件暂停 roboARM、保存保持位置并对 j1..j7 逐个发送 disable。恢复条件解除后 Error_tasks 自动清错、软启动、使能全部电机并恢复任务；没有独立人工重新使能步骤。电机型号或关节负载不能证明存在失电抱闸，故此路径存在机械臂下坠风险。
- Host.h 定义的 HOST_LINK_TIMEOUT_MS=500 ms 仅供 Host_IsOnline() 观测。该值不进入 Error_tasks 或机械臂控制策略；USB 断线本身不触发安全状态转移。USB 回调把“任意收到字节”的 tick 作为链路在线时间，不等同于最近一帧有效命令时间。
- Motor_DM::UpdateFeedback() 解码并保存错误码、位置、速度、扭矩、温度并增加 rx_cnt；未见周期比较 rx_cnt、逐轴反馈超时或基于 error 码的故障转移。Joint 的 inited 在首个反馈后置真，没有因之后反馈停更而清除的路径；上行 inited 是 j1..j6 锁存状态的 AND。

### ROS 2 上位机

- P5b 中 tzb_ws/src/lite_motion_planner/src/tzb_catch.cpp 发布机械臂关节目标到 /tzb_catch/arm_joint_command，默认 100 Hz；目标来自已插值的关节轨迹。它不是底盘 /cmd_vel 的运动接口。
- tzb_ws/src/serial/driver/src/node.cpp 的 rm_serial_driver 同时有历史底盘回调和机械臂桥接功能。P5b 已把底盘默认话题改为 /tzb/legacy_chassis_cmd；机械臂目标仍从 /tzb_catch/arm_joint_command 进入。节点按 100 Hz 周期发送 46 字节包，包内 arm_command_enabled 在首次收到有效命令后持续为 1，arm_sequence 递增。
- armCommandCallback() 不校验 JointState.header.stamp；有效位置写入 arm_target_position_，并把 have_arm_command_ 永久置真。ROS 命令停止后 timerCallback() 仍用缓存的目标继续生成并发送使能帧。非法新命令会被拒绝，但不会清掉此前缓存的有效目标。
- 串口重连会重置反馈分帧和反馈序号跟踪器，不清 have_arm_command_、缓存目标或夹爪目标。因此串口恢复后可能再次发送断线前目标。arm_sequence 在上位机递增，但 STM32 当前没有校验这个字段。
- 上位机对反馈帧做格式、非有限值、重复序号等校验并发布 /serial/arm_joint_state；没有反馈静默超时或逐轴反馈新鲜度消息。STM32 若在一帧中重复打包某轴旧缓存，上位机无法仅凭整帧序号发现该轴已停更。

## 主要安全发现

| 严重度 | 当前行为 | 风险与整改方向 |
| --- | --- | --- |
| 高 | ROS 命令时间戳不校验；命令缓存会无限续发；端口重连后缓存仍在；序号不形成端到端防重放。 | 旧轨迹可在 ROS 上游停更或串口恢复后继续运动。加入命令租约、会话/序号互锁、失效后清缓存；重新使能只接受新会话中的新命令。 |
| 高 | STM32 USB 在线判据未接入安全状态机；只按任意 USB 字节刷新在线 tick。 | USB 断线、ROS 崩溃和无效字节不能形成可用的命令看门狗。固件必须按有效控制帧与新鲜运动命令区分，并自主执行超时动作。 |
| 高 | 远控超时后当前策略会对全部 7 个电机失能，恢复后自动重新使能。 | 重力轴可能下坠，且遥控恢复可能触发自动恢复运动。需要将通信停止、受控急停和真正断能分层，并阻止自动恢复。 |
| 高 | 单轴 CAN 反馈停更不清除 inited；电机 error 未形成故障锁存。 | 状态反馈可能看似整帧新鲜，但个别关节使用旧位置继续闭环。应增加逐轴新鲜度/故障状态与动作处置。 |
| 高 | S2 最近缓存值可以授权 Host；遥控失联期间收到的主机帧会被解析，失联恢复后 Error_tasks 自动恢复。 | 控制权可能在失联后仍被旧拨杆值保留，且恢复没有人工确认。授权需同时依赖遥控在线、生命周期状态和唯一控制源。 |
| 中 | USB 46 字节帧 [15]=0 只代表不采纳/不更新本帧关节目标，并不是电机失能或清除旧目标的协议命令。 | 不可把清使能位误作“急停”或“清掉历史目标”。需明确 HOLD/STOP/ENABLE 与反馈确认语义，或在既有语义上验证受控流停止。 |
| 高 | 源码没有证明 DM 电机具备断电抱闸、机械自锁或负载保持能力；源代码的全轴 disable 会撤销 MIT 控制。 | 若重力轴在负载下失去保持力，臂可能快速下坠。必须确认电机/减速器/抱闸与载荷，不能只靠软件状态机消除此风险。 |

## 建议状态机

安全状态和控制权分开管理。任何时刻只能有一个控制源；不能用“消息还在发”推断命令源健康。

| 状态 | 进入条件 | 输出与退出条件 |
| --- | --- | --- |
| BOOT_INHIBIT | 上电、ROS 节点重启、协议重连、故障复位后 | 不接受旧运动目标；先收集六个受控关节的有效新反馈、无已知电机错误、遥控在线且中立。完成检查仍不自动运动。 |
| READY_HOLD | 健康条件成立且人工明确使能，但尚无新目标 | 保持当前实测位置/零速度；保留保持力。等待本次会话的新命令。 |
| ACTIVE_HOST | 人工选中上位机，遥控新鲜且处于授权挡位，命令序号/会话/位置有效 | 仅接受新鲜的 Host 目标；更新 command lease。 |
| ACTIVE_REMOTE | 人工切到遥控，遥控在线且摇杆已中立确认 | 仅遥控可产生运动目标；Host 目标无效且不得排队。 |
| STOPPING_HOLD | ROS 命令租约过期、通信暂失或控制权交接 | 立即使目标流失效，清除未来轨迹；让固件规划器受控减速，继续保持电机扭矩。检测到速度归零后转 READY_HOLD。不要发送全轴 disable。 |
| FAULT_LATCHED | 任一关节反馈过期、驱动器报错、无效/矛盾状态、协议/控制权错误 | 拒收运动目标，取消旧会话，报警并锁存。其余健康轴执行经确认的受控停止；故障轴动作取决于已验证的机械保持/制动策略。不得自动断能或自动恢复。 |
| RECOVERY_PENDING | 操作者发出人工恢复申请 | 核对故障消除、全轴反馈重新稳定、遥控在线且中立、机械区域安全；现场人工确认后回 READY_HOLD。仍需新会话、新序号和新命令才能进入 ACTIVE。 |

### 超时与输入规则

- ROS 命令租约从“最后一个有效、递增序号且属于当前会话的命令”起算，不以串口周期发送刷新。上游命令目标建议候选失效窗为 100 ms：当前规划器/桥接名义周期为 10 ms，固件已有 stream_hold_time=100 ms。该数值只供离线建模，需在目标 ThinkBook ROS 环境测量最差调度抖动后由你确认，不是已批准的生产参数。
- STM32 主机看门狗应以完整且可校验的有效帧为心跳；另有运动命令租约，不能让 bridge 以同一旧目标的 100 Hz 重发掩盖 Nav2/规划器停更。当前 Host_IsOnline 的 500 ms 与“任意字节”判据不能替代这两者。
- RC 有效样本当前 100 ms，遥控失联的生命周期处理当前 3000 ms。设计上 100 ms 后立即禁止用缓存摇杆继续运动并进入受控停止；3000 ms 不应作为运动仍可继续的窗口。改变现有 3 s 后 disable 的策略需你确认，且需先有重力保持评估。
- 六个 ROS 关节目标必须齐全、有限、处于配置限位内；NaN/Inf、名称缺失/重复、越界和会话/序号无效均不得更新租约。建议任何有限性/越界错误都会清掉当前运动命令并进入停止/锁存路径，不能保留旧目标继续执行。不得用静默钳位改变用户轨迹。
- 关节反馈超时应按每轴最近一帧 CAN feedback tick 判断，不应只看上位机收到的 USB 35 字节回复序号。阈值由实际 CAN feedback 周期与系统 jitter 测得后设置；当前源码没有可据以证明的统一毫秒阈值。
- 通过 ROS 重启、USB 重连、遥控器重新上线或清除通信错误均不自动恢复运动。清空旧目标/队列与待发轨迹；要求显式人工恢复，并从新鲜实测位置开始；首次运动需当前控制权下的新命令。

### 通信失联与下坠风险处置

普通 ROS/USB 失联不是“立即失能”命令。对于 CAN feedback 仍新鲜、无 motor error 的通信单故障，首选停止接收新目标，按已有流规划器减速到零并保持扭矩，再锁存等待恢复。源码已有 100 ms 无目标变化后令流速度目标归零的路径，适合作为设计候选，但未证明其失联瞬态、停车距离或负载保持足够。

单轴反馈过期/驱动报错与普通通信超时不同：固件可能无法安全地依据该轴陈旧状态闭环。建议立即锁存故障并禁止新轨迹，由已验证的本地安全策略处理故障轴；其他健康轴受控保持。没有实测证据时，软件不能选择“失能该轴”或“继续按旧反馈控该轴”。开展任何运动试验前，须使用机械支撑/防坠装置并确定故障轴可能下坠时的可控机械路径。

源码中 S1/S2 组合被称为急停，但审计没有证明它是独立硬件安全回路。真正的断能急停如撤销电机扭矩，必须与重力轴的失电抱闸、平衡机构或外部承托一起设计和测试。不得为了避免下坠而把“保持电机扭矩”当成物理急停替代品。

## 控制权与恢复要求

1. 上位机控制许可必须同时满足：当前状态为 READY_HOLD/ACTIVE_HOST、RC 在线、S2 明确选择 Host、急停未触发、每轴反馈新鲜、无锁存故障。遥控失联期间保留的 S2 值不能授权 Host。
2. Host → Remote 或 Remote → Host 先进入 STOPPING_HOLD，清理另一来源的缓存；停止确认后才能授予下一控制源。交接期间两个源都不能写运动目标。
3. 固件与 ROS bridge 应识别会话标识 + 单调命令序号。桥接器重启或串口重连开始新 session；重复/回退序号、旧 session 帧以及在故障锁存期间到达的帧不能更新目标或续租。
4. 故障清除不等于使能。人工恢复流程必须要求：现场可见的物理检查、故障原因消除、六轴反馈稳定、遥控中立、旧目标清空、受控状态确认、操作者二次确认。通过后只回 READY_HOLD；再次明确选择控制源并收到新命令才运动。

## 需你确认的安全策略

以下是实现前的产品/安全决策，P4d 没有替你作出决定：

1. **失联保持策略**：ROS 命令过期或 USB 中断时，是否采用“流停止 → 受控减速 → 扭矩保持”的首选路径；超时最终是保持扭矩，还是经机械承托确认后释放。
2. **遥控失联与急停策略**：是否取消当前遥控 3 s 后全轴 disable 和自动恢复行为；真正急停的硬件路径、失电抱闸/机械承托方案及是否允许某类急停撤销扭矩。
3. **反馈故障轴处置**：单轴反馈过期或电机报错时，对故障轴采用持续闭环保持、轴级失能、机械制动还是人工承托；这需要确认电机驱动行为、抱闸和整臂负载后才能定。
4. **重新使能来源**：由现场实体钥匙/按钮、遥控器中立后有意切换、还是现场操作员通过 ROS 服务并由实体使能输入二次确认。仅 ROS 按钮不提供现场可见性。
5. **候选租约阈值**：100 ms 命令 lease 是否接受；在目标计算机高负载、消息调度抖动、串口读写和机械臂最大允许减速度下测量之后才能锁定。

## 首次实机运动前必须解决的阻塞项

- 证明每个关节的反馈新鲜度和电机故障能被可靠发现；状态接口不能把重复旧轴值当成新反馈。
- 明确并审查通信超时、关节反馈超时、遥控失联、软件暂停和物理急停的分层策略；完成由你确认的失联扭矩/制动与人工恢复政策。
- 核实六轴电机/减速比/机械自锁/抱闸/失电行为及臂负载姿态，做支撑条件下的防坠风险验证；建立可触达且独立的物理急停。
- 实现并离线验证命令租约、逐轴反馈看门狗、错误锁存、控制源互斥、会话序号与无自动恢复；核对通信协议兼容性。
- 在有机械承托、隔离人员、限速和监督人的受控台架上，先测静止保持与失联减速，再做无负载单轴和逐步加载测试。离线模型不替代该验证。

## 分阶段实施顺序

1. 确认上面的失联、急停、故障轴扭矩和人工重新使能决策；核对物理抱闸/减速器和负载资料。
2. 定义协议 v2 的会话、序号、每轴反馈新鲜度/故障位、显式 HOLD/ARM 状态；保持旧协议时必须给出等价且可验证的语义。
3. 先实现纯 ROS bridge 的命令 lease、非法输入处置、缓存清除、断线重连锁存、状态诊断和单一命令源；在伪串口验证。
4. 再实现 STM32 每轴反馈看门狗、有效帧 host watchdog、状态机锁存和显式人工 re-arm；在主机桩/仿真中做故障注入。
5. 在机械支撑和物理急停可用的台架下，逐一验证保持力、受控停止距离、单轴掉反馈和驱动错误；经复核后才进入整臂/规划器联调。

## 离线测试结果

- 新增 tools/p4d_offline/test_arm_safety_model.py：对本报告建议行为的独立 Python 模型进行故障注入；覆盖上电互锁、命令租约超时、旧 session 重放、NaN/Inf/越界命令、单轴反馈失效锁存、遥控接管中立判定与人工恢复。该模型不是 ROS 节点、STM32 固件或真实电机的实现/验收。
