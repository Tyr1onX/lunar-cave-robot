# V0.3a Mac keyboard acceptance · SIMULATION only

This checklist is for a person using the Mac's physical keyboard. Run only after manually starting `tools/console-sim/run.sh` on NUC. Confirm the SwiftUI page says **SIMULATION** and the source is isolated ROS Domain 217 before pressing any key. Do not start the real robot stack.

| Step | Action | Expected result | Human result |
| --- | --- | --- | --- |
| 1 | Open **模拟驾驶**, click inside the map capture area, hold `W` for about one second | The pressed-key indicator lights; simulated odometry and the map pose move forward | ☐ Pass ☐ Fail |
| 2 | Hold `A`, then hold `W+A` together | The indicator tracks both keys; the simulated heading changes while the map pose advances | ☐ Pass ☐ Fail |
| 3 | Release every key | A single zero-velocity command is sent; the displayed simulated linear and angular speed return to zero | ☐ Pass ☐ Fail |
| 4 | Hold `W`, then click outside the map or switch to another macOS app | Focus loss clears all pressed keys and stops the simulation; velocity returns to zero | ☐ Pass ☐ Fail |
| 5 | Hold `W`, then select **测试驾驶舱** or another Console page | Leaving the page revokes the simulation token before the SSH forward closes; motion stops | ☐ Pass ☐ Fail |
| 6 | Return to **模拟驾驶**, click the map and press `D` | Focus can be acquired again and the new simulated command works; no stale key remains held | ☐ Pass ☐ Fail |

Record Mac model/macOS, Console commit, NUC simulation source SHA, date, and any observed exception below. The fixed local-only command endpoint is `/console_sim/cmd_vel`; the simulator watchdog remains 0.25 seconds. This is mathematical differential-drive simulation and does not validate physical six-wheel dynamics.

## Automated UI event check
