# V0.3c module test workbench

## Mac to NUC flow

1. On NUC, install the restricted user service once from the repository root:

   ```sh
   bash tools/console-agent/install-module-test-service.sh
   ```

   The installer enables `lunar-console-module-tests.service` for the current user. It binds only to `127.0.0.1:8769`; the service has no shell-command API and starts no robot process. The Mac app creates a fixed SSH local forward to this port.

2. On Mac, open **模块测试**, choose a categorized item, and click **一键执行**. The app refreshes the NUC test catalog immediately before requesting the fixed test ID.

3. Follow the streaming log and final status. Stop sends a cancellation request; the service terminates the complete child process group and reaps the child. A fixed per-test timeout applies even if the client disconnects.

4. Each completed run is written on NUC under `$XDG_STATE_HOME/lunar-cave-robot/module-tests/` as `<run-id>.json` and `<run-id>.log`. **保存报告** also exports the JSON report to Mac.

5. On service restart, systemd signals the runner first (`KillMode=mixed`). The runner cleans each test process group and saves active runs as `INTERRUPTED`; if the runner is forcibly killed, its next startup converts any persisted `running` report to `INTERRUPTED` and reloads the durable log. A lost Mac SSH forward leaves the NUC test running and the UI reports that its current state cannot be read until the tunnel returns.

## Allowlist and evidence

| Test ID | Mode | Reused test / input | Preconditions |
|---|---|---|---|
| `ros_environment` | OFFLINE | Existing ROS Humble environment check | ROS setup and fixed checker available |
| `arm_fk` | OFFLINE | Existing six-axis URDF FK test | URDF and script available |
| `yolo_offline` | OFFLINE | Existing ROS inference smoke using a generated blue-block image and CPU OpenVINO | Reuses `~/lunar-field-lab-p9i/models/blue_block`, its venv and prebuilt `build/tzb/install` overlay; no install/build |
| `chassis_protocol` | OFFLINE | P5a 14-byte protocol model plus P5b bridge source/config contract | Python and PyYAML; no UART/PTY opened |
| `p6_unit` | OFFLINE | Existing P6 task-state and fault unit tests | P6 source and Python 3 |
| `p6_scenarios` | SIMULATION | Existing six-case P6/Nav2 plus arm IK/RRTConnect mission suite | ROS Humble and colcon; reuses ROS dependencies and incrementally builds the current checkout |
| `p7_scenarios` | SIMULATION | Existing twelve-case P7 chassis/arm PTY fault suite | ROS Humble and colcon; reuses ROS dependencies, incrementally builds the current checkout, then uses temporary PTYs and synthetic feedback |
| `camera_readonly` | LIVE | Existing ROS topic graph, CameraInfo and diagnostics | Local Domain 0; does not subscribe to image frames |
| `mid360_readonly` | LIVE | Existing ROS topic graph, low-bandwidth IMU and diagnostics | Local Domain 0; does not subscribe to point clouds |
| `chassis_readonly` | LIVE | Existing serial-link status and diagnostics | Read-only; no velocity publish or serial open |
| `arm_readonly` | LIVE | Existing arm safety / joint feedback and diagnostics | Read-only; no arm command or device connection |

The POST request accepts only `{"test_id":"..."}`. The NUC maps that ID to one fixed script and fixed parameters. Arbitrary shell strings, paths, environment changes, topic names, or arguments are not accepted. The listener is loopback-only and is reached through the SSH alias. Each run is tagged `SIMULATION`, `OFFLINE`, or `LIVE`; the report captures SHA, input, parameters, elapsed time, result, and logs.

Reports store the run ID, UTC timestamps, mode, test and input source, fixed execution parameters, NUC repository SHA/dirty state, YOLO model bundle SHA-256 when applicable, elapsed time, terminal result, retained output, and log/report paths. Output retention is capped at 1 MiB per run. ROS test processes use Domain 187 and `ROS_LOCALHOST_ONLY=1`; the existing YOLO smoke script creates its own local-only test domain and uses a synthetic image.

## Read-only/live boundary and physical acceptance

- LIVE topic inspection reports the publishers and status that already exist on the NUC's local ROS Domain 0. Missing publishers are reported as `NO_PUBLISHER`; this is an inspection completion, not evidence the device is healthy.
- Camera image and MID-360 point-cloud streams are discovered but not subscribed by these checks. CameraInfo/IMU and status topic rates are sampled only if the corresponding fixed topic is already being published.
- No camera, MID-360, chassis, or arm driver is started. Chassis checks send no velocity and open no serial port; arm checks publish no motion command.
- Arm FK/IK/path planning use repository URDF, synthetic feedback, and P6/P7 simulation only. They do not verify servo zero, real joint limits, camera extrinsics, TCP, payload, collision clearance, or gripper polarity.
- Physical movement and sensor accuracy tests remain locked until deployment-specific safety and calibration conditions are documented.

OFFLINE and SIMULATION results, as well as LIVE read-only snapshots, cannot be presented as physical acceptance.
