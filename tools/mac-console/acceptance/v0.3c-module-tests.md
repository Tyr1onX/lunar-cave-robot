# V0.3c module test workbench

## Mac to NUC flow

1. On NUC, install the restricted user service once from the repository root:

   ```sh
   bash tools/console-agent/install-module-test-service.sh
   ```

   The installer enables `lunar-console-module-tests.service` for the current user. It binds only to `127.0.0.1:8769`; the service has no shell-command API and starts no robot process. The Mac app creates a fixed SSH local forward to this port.

2. On Mac, open **模块测试**, select ROS 环境检查, 机械臂 FK / 运动学, or YOLO 离线推理, and click **一键执行**. The app refreshes the NUC test catalog immediately before it requests a run.

3. Follow the streaming log and final status. Stop sends a cancellation request; the service terminates the complete child process group and reaps the child. A fixed per-test timeout applies even if the client disconnects.

4. Each completed run is written on NUC under `$XDG_STATE_HOME/lunar-cave-robot/module-tests/` as `<run-id>.json` and `<run-id>.log`. **保存报告** also exports the JSON report to Mac.

## Allowlist and evidence

| Test ID | Mode | Existing input / script | Availability |
|---|---|---|---|
| `ros_environment` | OFFLINE | ROS Humble environment check; no ROS node is launched | Available when the fixed check script exists |
| `arm_fk` | OFFLINE | `tzb_ws/src/serial/driver/test/test_tzb_urdf_joint_fk.py` and the existing `tzb_description` URDF | Available when the URDF and script exist |
| `yolo_offline` | OFFLINE | `tools/perception/offline_yolo_ros_smoke.py`, using the repository's generated synthetic blue-block frame | Locked until local model files and the built `yolo_node` ROS overlay are present |

The POST request accepts only `{"test_id":"..."}`. The NUC maps that ID to one fixed script and fixed parameters. Arbitrary shell strings, paths, environment changes, topic names, or arguments are not accepted. The listener is loopback-only and is reached through the SSH alias.

Reports store the run ID, UTC timestamps, mode, test and input source, fixed execution parameters, NUC repository SHA/dirty state, YOLO model bundle SHA-256 when applicable, elapsed time, terminal result, retained output, and log/report paths. Output retention is capped at 1 MiB per run. ROS test processes use Domain 187 and `ROS_LOCALHOST_ONLY=1`; the existing YOLO smoke script creates its own local-only test domain and uses a synthetic image.

## Not yet physically accepted

- Camera: device identity, stream quality, and calibration acceptance are not part of these offline tests.
- MID-360: no live point-cloud/timestamp/transform test is enabled.
- Chassis: no command or motion test is enabled.
- Arm: FK verifies the repository model and math only; it does not verify servo zero, TCP, payload, collision clearance, or motion on the arm.

These entries remain LIVE and locked. OFFLINE and SIMULATION results cannot be presented as physical acceptance.
